# AMGx SA-AMG Testing Setup

## Overview

This documents the validated testing configuration for comparing AMGx's SA-AMG
implementation against PETSc's GAMG. Both solvers produce **identical convergence**
(same iteration count) when given the same aggregates and omega.

## Test Problem

- **Grid**: 100×100, 2D 5-point Laplacian (10,000 DOFs)
- **Matrix file**: `poisson2d.mtx` (MatrixMarket, generated by PETSc ex2)
- **Coarsening**: MIS-k with distance=2, producing ~1429 aggregates

## Solver Configuration

| Parameter | PETSc Flag | AMGx Setting |
|-----------|------------|--------------|
| Outer solver | `-ksp_type richardson` | Richardson |
| Norm type | `-ksp_norm_type unpreconditioned` | unpreconditioned |
| Preconditioner | `-pc_type gamg -pc_gamg_type agg` | SA-AMG |
| SA smooths | `-pc_gamg_agg_nsmooths 1` | 1 |
| Coarsening | `-pc_gamg_mat_coarsen_type misk -pc_gamg_mat_coarsen_misk_distance 2` | MIS-k imported |
| Coarse limit | `-pc_gamg_coarse_eq_limit 2000` | 2000 |
| Smoother | `-mg_levels_ksp_type richardson -mg_levels_ksp_max_it 1` | Richardson, 1 sweep |
| Smoother PC | `-mg_levels_pc_type jacobi -mg_levels_pc_jacobi_type rowl1` | Jacobi-L1 |
| L1 scale | `-mg_levels_pc_jacobi_rowl1_scale 1` | scale=1 |
| Fix diagonal | `-mg_levels_pc_jacobi_fixdiagonal` | enabled |
| Coarse solve | `-mg_coarse_pc_type lu` | Dense LU |
| Tolerance | `-ksp_rtol 1e-8` | rtol=1e-8 |

## Key Parameters for Matching

### 1. Power Iterations for rho(D^{-1}A)

**File**: `include/aggregation/aggregation_amg_level.h` line 177

```cpp
ValueTypeB estimateSADampingFactor(int max_iter = 100);
```

Must be ≥100 to converge rho to ~1.97 (matching PETSc's Lanczos estimate).
With only 10 iterations, rho≈1.66 → wrong omega → wrong P → different iteration count.

### 2. Aggregate Import

AMGx imports aggregates from a text file via environment variable:
```bash
AMGX_IMPORT_AGGREGATES=gamg_aggs.txt ./test_mg_diag poisson2d.mtx
```

### 3. Aggregate Export from PETSc

**File**: `~/petsc/src/ksp/pc/impls/gamg/agg.c` (custom addition)

PETSc exports aggregates when `PETSC_EXPORT_AGGREGATES` env var is set:
```bash
PETSC_EXPORT_AGGREGATES=gamg_aggs.txt petsc_ex2 ...
```

The export code extracts aggregate IDs from P_tent's column indices (one entry per row).

## Running the Comparison

```bash
# On Perlmutter (interactive GPU node):
salloc -N 1 -C gpu -q interactive -t 00:30:00 -A m1516_g

cd ~/amgx-sa/build_perlmutter
bash ~/amgx-sa/scripts/run_mg_diag_compare.sh
```

The script:
1. Runs PETSc ex2 with `PETSC_EXPORT_AGGREGATES` → exports fresh aggregates
2. Runs AMGx test_mg_diag with `AMGX_IMPORT_AGGREGATES` → imports those aggregates
3. Both write MatrixMarket files for verification

## Matrix Verification Script

```bash
module load python
python3 ~/amgx-sa/scripts/verify_sa_matrices.py ~/amgx-sa/build_perlmutter/
```

Reads 6 MatrixMarket files (`{petsc,amgx}_{A,P_tent,P_smooth}.mtx`) and verifies:
- A matrices identical (rel_diff = 0)
- P_tent matrices identical (via same aggregates)
- P_smooth matches scipy reference `(I - omega*D^{-1}*A) * P_tent`
- Ac = P^T * A * P matches

## Lessons Learned

1. **MIS-k is non-deterministic** — even on 1 process, different runs give different aggregates.
   Always export/import aggregates for fair comparison.

2. **Power iteration count matters** — AMGx's default must be 100 to converge rho to ~1.97
   (matching PETSc's Lanczos estimate). With only 10 iterations, rho≈1.66 → wrong omega
   → wrong P → different iteration count (70 instead of 71).

3. **SpGEMM is correct** — Verified by cuSPARSE producing identical nnz. Initial suspicion of
   hash-based SpGEMM bug was wrong; the issue was simply different aggregates.

4. **P_tent norm matching ≠ same aggregates** — Norms can appear close (6 digits) with
   completely different aggregate assignments if aggregate size distributions are similar.
